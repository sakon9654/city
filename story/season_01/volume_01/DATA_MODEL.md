# มาตรฐานข้อมูลเพื่อรองรับนิยายระยะยาว

## 1. หน่วยข้อมูล
- **Canon**: กฎโลก พลัง องค์กร; มี `confirmed/provisional/undecided`.
- **Character**: รหัสถาวร, ชื่อ/นามแฝง, พลังเพียงหนึ่งอย่าง, แรงจูงใจ, ความสัมพันธ์, ความลับ, ตอนแรกที่ปรากฏ.
- **Event**: รหัส E ที่ไม่เปลี่ยน, เวลาในเรื่อง (อาจยังไม่ทราบ), บุคคล/สถานที่, สาเหตุ→ผล, แหล่งตอน, สถานะ approved/proposed.
- **Relationship**: รหัส R, คู่บุคคล/องค์กร, ประเภท, การเปลี่ยนตามเหตุการณ์, ระดับความรู้ทั้งสองฝ่าย.
- **Knowledge**: (บุคคล, ข้อเท็จจริง, ได้รู้จาก E ใด/ตอนใด, ความมั่นใจ) ไม่ใช่ความรู้ของผู้อ่าน.
- **Chapter**: ลำดับตอน, จุดเริ่ม–จบเวลาในเรื่อง, สถานะ, เหตุการณ์ใหม่, ข้อมูลเปิดเผย/ยังปิด.

## 2. Frontmatter สำหรับไฟล์ใหม่ (ตัวอย่าง ไม่ย้อนแทรกตอน APPROVED)
```yaml
---
id: city-s01-v01-c015
type: chapter
season: 1
volume: 1
chapter: 15
status: draft
timeline_after: E011
pov: []
characters: []
events: []
updated: 2026-10-14
---
```
ไม่บังคับใส่วันที่ในเรื่องจนยืนยันว่าเป็นวันที่เท่าใด

## 3. Obsidian
- ใช้ `[[relative/path|ชื่อแสดง]]` เชื่อม dashboard/แฟ้ม/เหตุการณ์ และใส่ Markdown link ปกติสำหรับเปิดใน GitHub เมื่อเหมาะสม
- อย่าย้าย/เปลี่ยนชื่อไฟล์ตอนเก่าที่ Approved เพราะทำให้ลิงก์และประวัติอ้างอิงแตก
- ยังไม่มีการยืนยัน plugin Obsidian ที่ใช้อยู่ (Dataview, Git, Sync); โครงนี้ใช้ Markdown เปล่าได้
- แก้ GitHub ได้ แต่ต้องตั้งการ sync ของเครื่องและ iPhone แยกต่างหาก

## 4. Checklist ก่อนเขียน/อนุมัติ
1. ตรวจ branch, working tree และ latest Git (ใน Vault จริง); ถ้ามี local edits อย่าทับ
2. อ่าน CURRENT_STATE หัวข้อใหม่สุด + ตอน Approved ล่าสุด + KNOWLEDGE_TIMELINE
3. อ่าน EVENT_LEDGER และ RELATIONSHIPS เฉพาะบุคคล/คดีที่เกี่ยวข้อง
4. เขียน Draft: ทุกข้อมูลใหม่เป็น proposed; ห้ามตัวละครรับรู้สิ่งที่ยังไม่เกิด
5. ก่อนอนุมัติ ตรวจเหตุ–ผล ลำดับสถานที่ เวลา ความสามารถ ความสัมพันธ์ และข้อมูลรั่ว
6. หลังผู้เขียนอนุมัติ เปลี่ยนทะเบียน proposed→approved เฉพาะเรื่องที่มีจริงในบทนั้น
7. แก้ CURRENT_STATE แบบมี **สรุปล่าสุดหัวเดียว** เพื่อลดข้อมูลสถานะขัดกัน; เก็บบันทึกเก่าในส่วนประวัติแยก

## 5. ข้อควรพัฒนาต่อ
- เพิ่มแฟ้มตัวละครสำคัญอื่นทีละรายโดยอ้างอิง Canon แทนการแต่งประวัติเอง
- แยก chronological timeline ระดับเหตุการณ์ทุกตอนเมื่อมีเวลาในเรื่องที่แน่นอน
- เพิ่ม location ledger และ factions ledger เมื่อภาค 2 เริ่มมีสถานที่/องค์กรซับซ้อนขึ้น
- ถ้าต้องการตรวจอัตโนมัติจริง ต้องสร้างสคริปต์ใน repo และทดสอบผล; **เอกสารนี้เป็นมาตรฐาน ไม่ใช่โค้ดตรวจที่ทำงานแล้ว**
